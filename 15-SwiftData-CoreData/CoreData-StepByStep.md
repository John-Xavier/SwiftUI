# Core Data — Step-by-Step

Use Core Data when you must support **iOS 13–16** (SwiftData needs iOS 17). Most of the boilerplate is generated by Xcode, so this is a guide rather than a code dump.

## 1. Add a Data Model file

`File → New → File → Core Data → Data Model`. Name it e.g. `Model.xcdatamodeld`.

> If you check **"Use Core Data"** when creating the project, Xcode scaffolds most of steps 2–3 for you.

## 2. Define an Entity

In the model editor:
1. Click **Add Entity**, rename it `TaskItem`.
2. Add **Attributes**: `title` (String), `isDone` (Boolean), `createdAt` (Date).
3. In the Data Model Inspector, set **Codegen = Class Definition** so Xcode auto-generates the `NSManagedObject` subclass. (You never see the generated file, but `TaskItem` is usable in code.)

## 3. Create the persistence container

Add a `PersistenceController` (Xcode's template gives you this):

```swift
import CoreData

struct PersistenceController {
    static let shared = PersistenceController()

    let container: NSPersistentContainer

    init(inMemory: Bool = false) {
        container = NSPersistentContainer(name: "Model")   // matches the .xcdatamodeld name
        if inMemory {
            container.persistentStoreDescriptions.first?.url = URL(fileURLWithPath: "/dev/null")
        }
        container.loadPersistentStores { _, error in
            if let error { fatalError("Core Data failed to load: \(error)") }
        }
        // Auto-merge changes made in background contexts.
        container.viewContext.automaticallyMergesChangesFromParent = true
    }
}
```

## 4. Inject the context into SwiftUI

```swift
@main
struct MyApp: App {
    let persistence = PersistenceController.shared

    var body: some Scene {
        WindowGroup {
            TaskListView()
                // The managed object context is how views read/write data.
                .environment(\.managedObjectContext, persistence.container.viewContext)
        }
    }
}
```

## 5. Read with @FetchRequest (the live query)

```swift
struct TaskListView: View {
    @Environment(\.managedObjectContext) private var context

    // Live fetch — the view updates automatically when data changes.
    @FetchRequest(
        sortDescriptors: [SortDescriptor(\TaskItem.createdAt, order: .reverse)]
    ) private var tasks: FetchedResults<TaskItem>

    var body: some View {
        List(tasks) { task in
            Text(task.title ?? "")   // Core Data attributes are Optional by default
        }
    }
}
```

## 6. Create / Update / Delete

```swift
// CREATE
let task = TaskItem(context: context)
task.title = "Buy milk"
task.createdAt = .now
save()

// UPDATE — just mutate, then save
task.isDone = true
save()

// DELETE
context.delete(task)
save()

// Always persist explicitly (unlike SwiftData, Core Data does NOT autosave):
private func save() {
    guard context.hasChanges else { return }
    do { try context.save() }
    catch { print("Save error: \(error)") }
}
```

## Gotchas

- **Attributes are Optional** in generated classes (`title: String?`) — unwrap or provide defaults.
- **Always `context.save()`** — Core Data does not autosave (SwiftData does).
- **Do heavy work on a background context** (`container.newBackgroundContext()`), then let `automaticallyMergesChangesFromParent` update the UI.
- **Preview crashes?** Use an in-memory `PersistenceController(inMemory: true)` in `#Preview`.

## Migrating to SwiftData later

SwiftData can open a Core Data store if the schemas match (`ModelConfiguration`).
For iOS 17+ only apps, prefer SwiftData from the start — see
[`SwiftDataExample.swift`](./SwiftDataExample.swift).
